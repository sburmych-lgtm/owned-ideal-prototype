# 00 · Власний порівняльний аудит: OWNED vs laserandme.com

**Дата:** 2026-08-08  
**Метод:** Playwright MCP, mobile ≈390×844 і desktop ≈1440×900  
**Об’єкти:**  
- Клієнт: https://web-production-f6bf3.up.railway.app/final/  
- Еталон: https://laserandme.com/  
- Репозиторій клієнта (структура): https://github.com/sburmych-lgtm/owned-final-r1  

**Скріни:** `docs/screenshots/`

---

## 1. Вердикт одним рядком

Еталон виграє **архітектурою доказу** (результат → цифри → послуги з цінами → відгуки). OWNED виграє **атмосферою і автентичністю** (реальний простір, неон, власні фото), але на desktop зараз виглядає як **розтягнутий мобільний стовпчик**, а не окрема композиція — і майже не конвертує через пізній/слабкий proof.

## 2. Що побачив уживо (серпень 2026)

### 2.1 OWNED — mobile

| Зона | Спостереження |
|------|----------------|
| Hero | Повноекранне темне відео/кадр з неоном OWNED; бренд великий і впізнаваний; H1 емоційний («Простір, де головний пріоритет — ти»); sticky «Записатися» одразу |
| Сила | Cinematic identity, справжній салон, не AI-шаблон |
| Слабкість | Універсальний H1; hero витрачає екран на атмосферу без SEO/позиціонування; sticky з’їдає висоту |
| Footer / booking | Форма «Запис» з полями Ім’я / Телефон / Коментар — функціонально ок, візуально «адмінська», без довіри поруч |

### 2.2 OWNED — desktop (критично)

| Зона | Спостереження |
|------|----------------|
| Hero | Контент у вузькій центральній колонці (~480–560px) всередині чорного поля; **немає десктопної редакційної композиції** |
| Nav | Гамбургер + sticky «ЗАПИСАТИСЬ» навіть на 1440px — патерн мобайла |
| Вердикт | Desktop = mobile stretch. Це головний architectural gap щодо будь-якого award-рівня medspa / beauty сайту |

### 2.3 laserandme.com — mobile + desktop

| Зона | Спостереження |
|------|----------------|
| Hero (сьогодні) | **Full-bleed фото процедури** + H1 «Embrace / Confidence.» + BOOK / OUR SERVICES. Mobile-аудит Opus (лише текст у hero) **вже не відповідає** поточній версії сайту — сайт еволюціонував |
| Proof | Early before/after + метрики; на desktop — чіткий editorial spread |
| Слабкості еталона | Плаваючі WhatsApp/IG перекривають контент; секція нагород перевантажена бейджами; золото на кремі — ризик контрасту; awards-смуга виглядає як «самовихваляння» |
| Desktop | Реальна широка композиція: зображення + текст + CTA, не «мобільна колонка по центру» |

## 3. Порівняльна матриця

| Критерій | OWNED зараз | laserandme | Можливість випередити обидва |
|----------|-------------|------------|-------------------------------|
| Бренд / атмосфера | Сильно | Середньо (generic luxury medspa) | Зберегти неон + Safe Town DNA |
| Порядок аргументів | Atmosphere-first | Proof-first | Proof-first **на OWNED голосі** |
| Desktop IA | Провал | Добре | Окрема desktop-композиція + editorial grids |
| Ціни | Відсутні | «Starting from $…» | «від ₴» на напрямах + повний /prices |
| Відгуки | Немає / слабко | 5.0 / 48+ | 4.9 / ~482 (верифікувати) — об’єктивна перевага |
| До/після | Пізно / плейсхолдер | Рано + галерея | 5–6 кейсів на головній + /gallery |
| Booking | Є | Є | Книжка без терли: години, маршрут, «від» |
| Motion | Autoplay video risk | Hover / slider | Neon Reveal + 1 BA affordance + reduced-motion |
| A11y sticky | Header/dock обрізають контент | Floating FABs overlap | Compact dock + IO hide logic |

## 4. Топ-проблеми OWNED (моя пріоритизація)

### P0
1. **Немає desktop-композиції** — найкритичніший gap vs еталон (і vs очікувань клієнта на 1440px).
2. **Доказ занадто пізно / занадто слабкий** для beauty conversion.
3. **Немає верифікованого Google rating strip** при тому, що це головний active бренду vs еталону.

### P1
4. H1 generic — не каже «складне волосся / Львів».
5. Немає вилок цін і годин роботи.
6. Sticky UI краде viewport / ріже заголовки.
7. Три секції атмосфери замість однієї.
8. Hair expertise не відокремлена від secondary beauty як acquisition wedge.

### P2
9. Contrast на eyebrow / золотавих лейблах.
10. Staging домен / preview артефакти (залежно від білду).
11. Booking форма без trust-мікрокопі поруч.

## 5. Що копіювати з еталона (дисципліна, не pixels)

1. Proof у перших 1.5–2 скролах після hero.  
2. Послуги як система з ціною «від».  
3. Повтор доказу (BA → gallery → reviews).  
4. Окремі маршрути: gallery / pricing / services.  
5. Desktop ≠ mobile: справжні двоколонкові глави.

### Що НЕ копіювати

- Купу awards-бейджів на екран.  
- Floating messenger buttons поверх контенту.  
- Gold-on-cream як масовий акцент.  
- Нумерацію послуг 01–08 без сенсу послідовності.

---

## 6. Моя design thesis для прототипу

**OWNED = editorial hair house з конверсійною дисципліною medspa.**

- Зберігаємо: ink / bone / moss, неон як *світло*, serif display, cinematic hero, засновницю, Safe Town.  
- Переписуємо: порядок секцій, H1, trust, BA, desktop layout, booking hygiene.  
- Сигнатура: **Neon Reveal** (SVG mark, ~600ms) — не WebGL-hero.  
- Job сторінки: **довіра → зрозуміти експертизу → записатися**.

## 8. Обмеження методу

- Код клієнтського репо на Railway не розбирав пофайлово в цьому прогоні (рендер + audits + handoff docs).  
- Рейтинг Google **потребує верифікації** перед продакшн-хардкодом.  
- Фото в прототипі можуть бути тимчасовими — не позиціонуються як «документовані клієнтські кейси OWNED».
